# กาชา (rarity capsule) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (founder chose inline execution with an opus reviewer per task). Steps use checkbox (`- [ ]`) syntax.

**Goal:** A fan ticks "สุ่มกาชา" with a tip after seeing the rarity odds. The pull is drawn on confirm from the box the fan saw. A capsule reveal plays on `/overlay/<u>/gacha`, and the prize goes into the creator's to-do list.

**Architecture:**
- Pure rules live in `src/lib/gacha.ts`. Odds, rebalance and draw already exist; the snapshot and the money check are new.
- The server module is `src/lib/gacha-server.ts`, holding the box read and version, the snapshot build, the draw, cancel, overlay claim and to-do items. It mirrors `wheel-server.ts`.

**Tech Stack:** Next 16, React 19, Prisma 7, next-intl, `node --test`.

**Spec:** `docs/superpowers/specs/2026-10-23-gacha-design.md`. Rulings K1–K11 override the earlier text.

## Global Constraints

- **Copy:** th/en parity, no emoji, gender-neutral.
- **Schema:** goes into the unapplied feature_hub migration, with RLS on new tables.
- **Lock order:** Tip → Wheel → User.
- **Fan protection:** never block a tip (`gachaDropped`) and never raise the amount.
- **Never:** print overlay keys, use the production DB, or push.

## Review Focus

1. The fan is drawn from exactly the odds and prizes they saw, even if the creator edits before a manual confirm (K1).
2. Reject → re-confirm returns the same pull without replaying it. A dropped or forced pull never draws later (K2).
3. The wheel's `wheel_empty` 409 and the spin retry behave exactly as before when gacha is also ticked.
4. To-do: ticking a gacha item done or undone works, and wheel and combo items still work (K4).
5. A prize with money in its text is refused, with a clear message (K11).

### Task 2: Schema, server module, tip pipeline, to-do, rules

**Files:**
- `prisma/schema.prisma`, the migration
- `src/lib/gacha-server.ts` (new)
- `src/lib/tip-hooks.ts`
- `src/app/api/tips/route.ts`, `src/app/api/tips/[id]/route.ts`
- `src/lib/wheel-server.ts` (`todoItems`, `TodoItem`)
- `src/app/api/wheels/spins/route.ts`
- `src/app/api/gacha/rules/route.ts` (new)
- `src/app/api/overlay/[username]/gacha/route.ts` (new)
- `src/lib/overlay-test.ts` (`pushGachaTest`/`readGachaTest`)

**Schema:**
- User: `gachaEnabled false`, `gachaPrice 50`, `gachaCommon 70`, `gachaRare 25`, `gachaEpic 5`, `gachaVersion 0`, `gachaColor?`, `gachaRulesAcceptedAt?`.
- `GachaPrize`: `{id, userId, rarity, text, imageUrl?, noAction false, position, deletedAt?, createdAt}`, `@@index([userId])`.
- `Tip`: `gachaPull Boolean false`, `gachaBox Json?`.
- `GachaPull`: `{id, userId, tipId @unique, rarity, prizeId?, prizeText, imageUrl?, noAction, status SpinStatus (reuse ACTIVE/CANCELLED), confirmedAt, playedAt?, doneAt?, createdAt}`, `@@index([userId, status])`.

**Server module** (`gacha-server.ts`):
- `gachaForFans(userId)`: `{version, price, odds (display), tiers: {rarity, prizes: text[]}[]} | null` when the card is on and something can come out.
- `gachaSnapshot(userId, seenVersion)`: `GachaBox | null`.
- `gachaStartTx(tx, tipId, now)`: `"started" | "restored" | "none"`. It draws with `crypto.randomInt` from `tip.gachaBox`, and restores a CANCELLED pull.
- `cancelGachaTx(tx, tipId)`.
- `nextOverlayPull(userId, now)`.
- `gachaTodo(userId, status)`, merged into `todoItems`.
- `setGachaEnabled`, which requires rules.

**Tip routes:**
- `POST /api/tips`: if `gachaPull` with `gachaSeen`, then check the card, the floor (K8) and the snapshot → `Tip.gachaPull` + `gachaBox`, or `gachaDropped`. Auto-confirm draws in the main transaction after the spin, with its own retry using `stillConfirmed`. On failure, `gachaPull=false` and `gachaDropped`.
- `PATCH /api/tips/[id]` confirm: after `startSpinTx`, `gachaStartTx`. The reject path is unchanged (the hook handles it).

**Hooks:** `onTipRejectedTx` calls `cancelGachaTx` after `cancelSpinTx`.

**To-do:**
- `TodoItem` gets `kind: "gacha"` and `rarity: Rarity | null`.
- `PATCH /api/wheels/spins` gets a gacha branch (owner-scoped `doneAt`).

**Rules:** `POST /api/gacha/rules` sets `gachaRulesAcceptedAt` and enables the gacha.

**Overlay feed:** `GET /api/overlay/<u>/gacha?key=` returns `{pull | null, color}`, with the Redis test first.

- [ ] Write the schema and SQL. Run migrate on a fresh DB and check the diff is empty. Run `db execute` locally (dev server stopped) and `generate`.
- [ ] Implement.
- [ ] Verify through the routes:
  - a tip with a pull, then confirm, gives exactly one pull from the snapshot;
  - the creator edits the odds to 0/0/100 before confirm, and the pull still uses the snapshot;
  - a stale `gachaSeen` gives dropped;
  - reject cancels; re-confirm gives the same prize;
  - the overlay claims it once;
  - the to-do item can be ticked done and undone;
  - spin + gacha together: both drawn.
- [ ] Commit.

### Task 3: Overlay capsule reveal

**Files:** `src/app/overlay/[username]/gacha/page.tsx`, `src/components/overlay/GachaOverlayClient.tsx`

- Hidden while idle.
- When a pull arrives: the capsule drops (0.8 s), shakes (1.2 s), then opens into the rarity colour. Common is slate `#94a3b8`, rare is violet `#8b5cf6`, epic is gold `#f59e0b` with sparkles. The reveal card ("<fan> ได้ <prize>!", rarity badge, optional image) shows for 4 s, then the next pull plays.
- Polls every 3 s, only while idle.
- Plain CSS keyframes in an inline `<style>`.

- [ ] Check in an iframe: a test pull reveals with the right colour; a real pull is claimed once (a second iframe doesn't replay it).
