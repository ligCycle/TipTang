# Combo Tip Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Confirmed tips from 3+ fans within 5 minutes (while the combo OBS link is open) start a "คอมโบทิป" on stream; every counted tip fills a level bar and resets a 5-minute countdown; reaching a level unlocks the creator's reward into the to-do list; the end shows a summary; then a 1-hour cooldown.

**Architecture:** Pure rules (bar sizes, adding/removing baht, fan counting, level-table validation, defaults) in `src/lib/combo.ts` with unit tests. Combo state lives in new tables folded into the unapplied feature-hub migration. `src/lib/combo-server.ts` owns the lifecycle inside the existing tip confirm/reject transactions (same pattern as `startSpinTx`/`cancelSpinTx`) with the creator's `User` row locked; there is no background job, so expiry is applied lazily on every confirm/reject and every combo-feed read. The to-do list (`todoItems`, `SpinTodo`, `/todo` overlay) is generalised to hold wheel results and combo rewards.

**Tech Stack:** Next.js 16 App Router (read `node_modules/next/dist/docs/` first), React 19, next-intl (th/en parity), Prisma 7 + hand-written SQL, Tailwind 4, `node --test`.

**Spec:** `docs/superpowers/specs/2026-10-23-combo-tip-design.md` (approved 2026-10-23). Mockups: `.superpowers/brainstorm/1407-1792721253/content/hype-v2.html`, `combo-settings-v2.html`.

## Global Constraints

- Name "คอมโบทิป" everywhere; never "Hype Train". No emoji in UI, gender-neutral copy, th/en parity (OBS overlays Thai-only like the alert/timer overlays), autosave.
- Fixed rules: start = 3 different fans (trimmed, case-insensitive names; all empty names = one fan) confirmed within 5 min; countdown 5 min from the last counted tip; cooldown 1 h after a combo ends; summary ~15 s; overlay "live" = combo link polled within the last 2 min.
- Only CONFIRMED tips count, timed by confirmation; shop orders never count; a tip counts only if the combo link was live and the card on at its confirmation.
- Bar sizes: typical tip = median of confirmed tips in the last 30 days if ≥ 5 tips, else max(creator minimum, ฿50); level 1 = typical × 2.5 / 3.5 / 5 (easy/medium/hard), each next level × 1.3 (chained on the unrounded value), rounded to the nearest ฿10, minimum ฿10; "custom" uses the creator's baht per row. Past the last row: last row's size, no reward. Sizes and rewards are snapshotted at combo start.
- Row N = baht needed while at level N; its reward is unlocked when level N is reached; level 1 has no reward. Extra baht carries over (one tip can pass several levels).
- Default rows: L1 (no reward), L2 "พูดสำเนียงที่แชทเลือก 1 นาที", L3 "ร้อง 1 เพลงที่แชทขอ", L4 "ตอบคำถามแชท 3 ข้อ", L5 "ไลฟ์ต่ออีก 30 นาที".
- Limits: ≤ 20 rows; reward text ≤ 40 chars; baht per row 1–100000 whole baht.
- Reject of a counted tip: subtract from total; levels and rewards stay; current bar floors at 0. Re-confirm = a new confirmation at that moment. Card off ends a running combo at once with no summary.
- Colour chain: comboColor → alertColor → brand pink.
- Schema folds into `prisma/migrations/20261018000000_feature_hub/migration.sql`. Never touch the production DB: every Prisma CLI call passes local `DIRECT_URL` inline and checks `npx prisma migrate status` host first. Local DB: prisma dev `tiptang-hub2` at `localhost:51230`. Push only on "merge push". Lint: only the 5 existing errors.

## Review Focus

1. Two tips confirmed at the same moment that both fill the last baht of a level → the level unlocks once and its reward appears once in the to-do list (Task 3 parallel-confirm check).
2. A creator confirms a backlog of pending tips after the stream with the combo link closed → nothing starts and no cooldown begins (Task 3 check with no overlay polling).
3. A single ฿1,000 tip at level 1 with small bars → passes several levels, each reward lands once, the overlay celebrates each level in turn (Task 1 `addAmount` test + Task 5 check).
4. The countdown passes while no one polls (OBS closed) → the next read ends the combo at `lastTipAt + 5 min`, the cooldown counts from then, and a late-opened overlay doesn't replay an old summary (Task 3 + Task 5).
5. A creator with no tip history, or only ฿1 tips → bars are still sensible (≥ ฿10, from max(min, ฿50)) and the page shows the numbers (Task 1 `typicalTip`/`autoSizes` tests).

### Task 3: Combo engine on confirm / reject, to-do list for rewards

**Files:** Create `src/lib/combo-server.ts`; Modify `src/app/api/tips/[id]/route.ts`, `src/app/api/tips/route.ts`, `src/lib/wheel-server.ts` (`todoItems`), `src/app/api/wheels/spins/route.ts`, `src/components/features/SpinTodo.tsx`, `src/components/overlay/TodoOverlayClient.tsx`, `src/app/api/overlay/[username]/todo/route.ts`

**Interfaces:**
- Consumes: Task 1 (`sizesFor`, `typicalTip`, `addAmount`, `removeAmount`, `countFans`, constants); Task 2 models; `Tx` = `Prisma.TransactionClient`.
- Produces:
  - `comboConfirmTx(tx: Tx, tipId: string, now: Date): Promise<void>` — locks the creator's `User` row (`SELECT … FOR UPDATE`), `endIfExpiredTx`; sets `tip.comboEligible` when card on and `comboOverlaySeenAt ≥ now − LIVE_MS`; if eligible: an ACTIVE combo → add (ComboTip with `levelAfter`, `lastTipAt = now`, ComboReward rows for each reached level that has reward text, `createMany … skipDuplicates`); else if no cooldown and `countFans` of eligible confirmed tips in `[now − WINDOW_MS, now]` not in any combo ≥ `START_FANS` → create Combo (snapshot `sizesFor(rows, difficulty, typicalTip(last-30-day amounts, minTipAmount))` and rewards) and add those tips oldest first.
  - `comboRejectTx(tx: Tx, tipId: string, now: Date): Promise<void>` — counted ComboTip → `counted=false`; `total −= amount`; if its combo is ACTIVE, `removeAmount`.
  - `endIfExpiredTx(tx: Tx, userId: string, now: Date)` — ACTIVE and `now ≥ lastTipAt + COUNTDOWN_MS` → ENDED, `endedAt = lastTipAt + COUNTDOWN_MS`, `comboCooldownUntil = endedAt + COOLDOWN_MS`.
  - `stopComboTx(tx, userId)` — ACTIVE → STOPPED (used by Task 4's toggle off).
  - `applyCombo(tipId: string): Promise<void>` — `prisma.$transaction(tx => comboConfirmTx(tx, tipId, new Date()))` for tips confirmed on arrival.
  - PATCH `/api/tips/[id]`: inside the existing transaction, after a fresh CONFIRMED → `comboConfirmTx`; on reject from CONFIRMED → `comboRejectTx`. POST `/api/tips`: after create with status CONFIRMED → `await applyCombo(tip.id)` (errors logged, never fail the tip).
  - `TodoItem` gains `kind: "wheel" | "combo"` and `level: number | null` (`fan` = "" for combo); `todoItems` merges both (open: oldest first by `confirmedAt`/`reachedAt`; done: newest first; 30-day window); spins PATCH body `{ id, done, kind? }` (default "wheel"); `SpinTodo` + to-do overlay show "คอมโบเลเวล N" (th) / "Combo level N" (en, dashboard only) where wheel items show the fan.

- [ ] **Step 2: Fetch checks on the local test account** (set `comboEnabled`, keep a fake "live" by calling the combo feed from Task 5 — until it exists, set `comboOverlaySeenAt = now()` via SQL before each step): 3 tips with distinct names confirmed → combo ACTIVE at level 1 with the right snapshot; 2 tips with the same name + 1 anonymous → no start; a ฿1,000 tip → several ComboReward rows once each; two tips filling the same level confirmed in parallel → one ComboReward for it; reject a counted tip → total drops, level unchanged; set `lastTipAt` back 6 min → next confirm ends it and sets cooldown; tips during cooldown don't start one; with `comboOverlaySeenAt` null, confirming 3 backlog tips starts nothing and sets no cooldown; to-do list shows the rewards with "คอมโบเลเวล N", ticking works.
