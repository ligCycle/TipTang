# ตีบอส (boss raid) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** While the boss OBS link is open, confirmed tips damage the current boss (1 baht = 1 HP). Overkill carries over. Each defeated boss plays a kill banner once, and its reward goes to the to-do list.

**Spec:** `docs/superpowers/specs/2026-10-24-boss-design.md`, plus the builder-check rulings once they are added. Pure rules: `src/lib/boss.ts` (done, 9 tests).

## Global Constraints

- **Copy:** th/en parity, no emoji, gender-neutral.
- **Schema:** goes into the feature_hub migration, with RLS on.
- **Locks:** Tip → Wheel → User. The creator lock comes before any insert that has a key to User or Tip (the FK share-lock lesson from P5/P8).
- **Live-only:** damage counts only while the boss link was seen within `LIVE_MS`.
- **Never:** print overlay keys, use the production DB, or push.

## Review Focus

1. Parallel confirms can't deadlock on the BossHit/BossKill inserts.
2. A reject removes only that tip's damage on the current boss. A boss that is already dead stays dead.
3. With the overlay closed, nothing counts. With it open, a big tip kills several bosses, and each kill plays once across sources (more than 3 collapse into a summary).
4. Editing or reordering the list mid-run keeps the run sane (B5). Reset starts again from boss 1.
5. A reward with money in it is refused.
